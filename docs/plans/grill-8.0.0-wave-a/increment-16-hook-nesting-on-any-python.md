### Increment 16: the hooks detect nested stdin on any Python
- Item: a defect the orchestrator found on the untouched round base, so it predates this round: under Python 3.14 `bash tests/test-prompt-hooks.sh` fails X145. Python 3.14's JSON decoder raises no `RecursionError` on 100 000 nested `[`: `json.loads('[' * 100000)` raises `JSONDecodeError`, a `ValueError`, and balanced deep nesting parses. `route-hook.py` reads nesting only from `RecursionError`, so it takes its silent not-JSON branch and the pointer line is lost. `status-hook.py` makes the same assumption. Every plant that moves to Python 3.14 inherits it
- Spec contracts: SPEC-0003/ROUTE_HOOK_UNPASSABLE_PROMPT_FAILS_OPEN (a prompt the hook cannot pass on still gets the pointer line), through SPEC-0003's failure mode UNEXPECTED_EXCEPTION and its §10 row, X145
- Files touched: `integrations/claude-code/route-hook.py` (one home for a fixed stdin nesting limit and a scan that counts open arrays and objects outside strings before the parse; the `RecursionError` guard stays as a second guard); `integrations/claude-code/status-hook.py` (it uses that scan through the sibling it already loads, and keeps its own `RecursionError` guard); `tests/test-prompt-hooks.sh`; `docs/specs/SPEC-0003-per-prompt-injection.md` (§6 constant, §7 UNEXPECTED_EXCEPTION wording, §10 row, §12 entry)
- Tests to write (RED): the existing X145 is the RED, and at most 1 more case: a valid envelope nested past the limit gets the same answer as X145, and a prompt that carries many `[` inside its string is routed as usual
- Behavior added: on every Python, stdin nested past the limit gives `route-hook.py` the pointer line and exactly one stderr line, and gives `status-hook.py` its summary and at most one stderr line. The answer stops depending on which exception the interpreter's parser raises
