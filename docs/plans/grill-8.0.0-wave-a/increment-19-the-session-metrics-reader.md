### Increment 19: the session-metrics reader
- Item: the owner decided on 2026-10-05 the direction: a reader enforces the session-metrics block of a Tier 2 or Tier 3 delivery entry. Until this increment the block was a written rule with no reader, so a delivery could ship without it and nothing said so. The reader is a new seed tool placed into every plant.
- Spec contracts: SPEC-0006/METRICS_FILLED_ENTRY_PASSES, SPEC-0006/METRICS_NOT_RECORDED_WITH_REASON_IS_FILLED, SPEC-0006/METRICS_BLOCK_MISSING_FAILS, SPEC-0006/METRICS_LINE_MISSING_FAILS, SPEC-0006/METRICS_LINE_EMPTY_FAILS, SPEC-0006/METRICS_NOT_RECORDED_WITHOUT_REASON_FAILS, SPEC-0006/METRICS_LOW_TIER_EXEMPT, SPEC-0006/METRICS_COMPACT_ENTRY_EXEMPT, SPEC-0006/METRICS_ENTRIES_BEFORE_SINCE_NOT_JUDGED, SPEC-0006/METRICS_OTHER_ENTRY_DEFECT_IS_A_NOTE, SPEC-0006/METRICS_NO_ENTRY_SINCE_FAILS, SPEC-0006/METRICS_MISSING_CHANGELOG_FAILS, SPEC-0006/METRICS_SINCE_REQUIRED, SPEC-0006/METRICS_ENTRY_HEADINGS_RECOGNIZED, SPEC-0006/METRICS_SECTION_HEADINGS_STAY_IN_ENTRY, SPEC-0006/METRICS_LABELS_FROM_DELIVER_NODE, SPEC-0006/METRICS_SHIPPED_DELIVER_NODE_PARSES, SPEC-0006/METRICS_DELIVER_NODE_UNPARSEABLE_FAILS_LOUD, SPEC-0006/METRICS_UNREADABLE_CHANGELOG_FAILS_LOUD, SPEC-0006/METRICS_ALL_REPORTS_EVERY_ENTRY, SPEC-0006/METRICS_READER_RUNS_IN_A_FRESH_PLANT, with the failure modes SPEC-0006 §7 lists and the acceptance criteria AC-1 to AC-9 (declared in this increment's specify step, `docs/specs/SPEC-0006-session-metrics.md`, a new spec); round 2 adds SPEC-0006/METRICS_LINES_COUNTED_AS_GREP_DOES, SPEC-0006/METRICS_LEADING_BOM_IGNORED, SPEC-0006/METRICS_DATED_HEADING_ENDS_ENTRY, with the failure DATED_SUBHEADING_IN_ENTRY. Five rules this increment first declared as contracts, the Tier-unreadable hint, markup stripping in the Tier value, a `not recorded` Tier declaring none, the last date in a heading, and a fenced line in the block, were later demoted to reading rules by the consolidation increment (increment 20); SPEC-0006 §4 marks each retired, and §6 keeps it as a reading rule with its coverage loss
- Files touched: `tools/session-metrics.py` (new, stdlib, writes nothing; a lint role, `--since` and `--entry LINE`, and query roles, `--all [--json]` and `--labels`; it reads the block's labels from the deliver node at run time and holds no copy of the list); `install.sh` (one `place_file` that places the reader at `docs/graph/session-metrics.py`); `manifest.json` (its `tools` map entry); `tools/graft-audit.py` (a `DELIVERED_TOOLS` entry, so the reader's fast-forward backup is mapped); `protocols/deliver.md` and `protocols/canonize.md` (the shipping condition names the reader, `--since`, `--entry` and `not recorded: <reason>`); `tests/test-session-metrics.sh` (new), `tests/fixtures/session-metrics/` (new: the deliver node's block, the block with an extra label, the block with no fence); `tests/test-full-install.sh` (E14); `tests/run.sh` (one step) and `tools/gate-registry.py` (its classification, fixtures and scope); `docs/specs/SPEC-0006-session-metrics.md`
- Tests to write (RED): one case per contract, X397 to X417 in `tests/test-session-metrics.sh`, plus E14 in `tests/test-full-install.sh`; arms for the failure modes the architect closed run alone. Fixtures are synthetic changelogs built under a temp directory and a fixed `--since` date, never a real plant's
- Behavior added: `python3 docs/graph/session-metrics.py --since <date>` in a plant judges every Tier 2 or Tier 3 delivery entry dated on or after that date. An entry with a filled block passes, and `not recorded: <reason>` counts as filled; a missing block, a missing or empty line, a bare `not recorded` or an unreadable tier fails. Tier 0 and Tier 1 entries, compact entries and entries before the date are not judged. With `--entry`, a defect in another same-day entry is a note, not a failure. A missing deliver block, an unreadable changelog or a named changelog that does not exist is fatal and named. `--all --json` reports every entry's raw values for harvest

- Round 2 (2026-10-05): an independent review of the GREEN found one major defect and several minor ones, and the spec gained seven contracts to hold the fixes. The major one: the reader split lines with Python's `splitlines()`, which also breaks on U+2028, a form feed, U+0085 and other separators that `grep -n` does not count. So the line `--entry` names, which deliver tells the session to take from `grep -n`, could miss its heading and exit 2 with a false message. The minor ones: a leading BOM hid a heading on line 1; a fenced line inside the block was read as a metrics line; a dated heading inside an entry did not end it, so an entry could borrow a later block; the heading pattern accepted a colon and a bare hyphen that §6 does not name; and a Tier value in backticks, asterisks or underscores was read as no tier. RED: six cases failed for the right reason before any code change, for example `FAIL: [METRICS_LINES_COUNTED_AS_GREP_DOES] expected exit 0, got 2 ... --entry 9` with `ENTRY_LINE_NOT_A_DELIVERY_HEADING: line 9 is not a delivery heading`, `FAIL: [METRICS_TIER_IN_MARKUP_READ] expected exit 0, got 1` with `METRICS_TIER_UNREADABLE` on each marked-up value, `FAIL: [METRICS_DATED_HEADING_ENDS_ENTRY] expected exit 1, got 0`, `FAIL: [METRICS_FENCED_LINE_NOT_A_METRICS_LINE] expected exit 0, got 1`, `FAIL: [METRICS_LEADING_BOM_IGNORED] expected exit 0, got 2 ... --entry 1`, and the widened `case_entry_headings`.
