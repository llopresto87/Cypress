## What it is
H2 is an open-source SQL database written in Java, published as
`com.h2database:h2` (driver class `org.h2.Driver`). It runs embedded in the
application's JVM or as a server, keeps a database in memory or in files, ships
a browser-based console, and supports multi-version concurrency and encrypted
database files. In Spring applications it serves mostly as the in-memory
database for tests and local runs; Spring Boot manages its version in the Boot
dependency BOM. Upstream home: https://h2database.com (manual), source on
GitHub (`h2database/h2database`).

The upstream FAQ names the areas it tests less well for production use: other
platforms, `AUTO_SERVER` and `AUTO_RECONNECT`, cluster mode, two-phase commit
and savepoints, fulltext search, and LOBs over 2 GB.

## Install, setup and configuration
- Add `com.h2database:h2` (runtime or test scope) and let the Boot BOM pick the
  version. The 2.x line runs on Java 11 or newer.
- **URL forms.** Embedded file database: `jdbc:h2:[file:]<path>/<name>` (a
  relative path starts at the working directory, `~/` is the home directory).
  In-memory: `jdbc:h2:mem:` is private to one connection; `jdbc:h2:mem:<name>`
  is shared inside one JVM and class loader. Server: `jdbc:h2:tcp://host/<name>`.
  Settings follow as `;KEY=VALUE`.
- **In-memory lifetime.** By default (`DB_CLOSE_DELAY=0`) an in-memory database
  is closed, and its content lost, when its last connection closes.
  `DB_CLOSE_DELAY=-1` keeps it for the life of the JVM (it can leak memory;
  `SHUTDOWN` removes it); a positive value delays the close by that many
  seconds. `DB_CLOSE_ON_EXIT=FALSE` stops H2's shutdown hook from closing the
  database.
- **Connection-time SQL.** `INIT=<SQL>` runs SQL whenever a connection opens,
  for example `INIT=RUNSCRIPT FROM 'classpath-or-file.sql'`; separate several
  statements with an escaped semicolon `\;`. `IFEXISTS=TRUE` opens only a
  database that already exists. `IGNORE_UNKNOWN_SETTINGS=TRUE` ignores settings
  the engine does not know.
- **Compatibility modes.** `MODE=` takes DB2, Derby, HSQLDB, MSSQLServer,
  MySQL, Oracle or PostgreSQL. Each mode adds only the behaviours its manual
  entry lists. For MySQL the manual gives
  `jdbc:h2:mem:test;MODE=MySQL;DATABASE_TO_LOWER=TRUE`; do not change
  `DATABASE_TO_LOWER` after the database exists. In that mode
  `ON DUPLICATE KEY UPDATE` works, `INSERT IGNORE` and `REPLACE INTO` work in
  part, floating-point to integer conversion rounds, and trailing spaces of
  CHAR values are trimmed.
- **Keywords as names.** `SET NON_KEYWORDS ...` (or `NON_KEYWORDS=` in the URL)
  turns listed keywords into plain identifiers for the session; the manual
  prefers quoting the identifier.
- **Spring Boot.** With an embedded database on the class path and no
  `spring.datasource.url`, Boot configures an embedded database (H2, HSQL or
  Derby) on its own. `spring.datasource.embedded-database-connection` picks one
  when several are present (`none` turns the behaviour off). JPA schema
  generation (`ddl-auto`) defaults to on only for embedded databases. When a
  test uses an embedded H2, keep `DB_CLOSE_ON_EXIT=FALSE` so Boot, not H2's
  hook, decides when it closes.
- **Console.** Boot auto-configures the H2 console for a servlet application
  when developer tools are in use (on Boot 4, also only with the
  `spring-boot-h2console` module on the class path); otherwise `spring.h2.console.enabled=true`
  turns it on. The default path is `/h2-console` (`spring.h2.console.path`).

## Core API / usage shape
- Plain JDBC through `org.h2.Driver`; `org.h2.jdbcx.JdbcDataSource` is the
  data-source class. H2 has a simple built-in connection pool; an external pool
  is the usual alternative.
- Server tools: a web server (for the console), a TCP server for client/server
  connections, and a PostgreSQL-protocol server. Starting a server opens no
  database; a database opens when a client connects. Remote creation of a
  database is refused unless the server runs with `-ifNotExists`.
- Generated keys: declare `GENERATED BY DEFAULT AS IDENTITY` or
  `GENERATED ALWAYS AS IDENTITY` columns and read the values with
  `Statement.getGeneratedKeys()`.
- `CREATE SCHEMA [IF NOT EXISTS] <name>`: H2 has real schemas and an
  information schema.
- With Hibernate, use `H2Dialect` where possible. `H2Dialect` does not support
  the compatibility modes, so a database run under `MODE=MySQL` is used with
  the Hibernate dialect of the emulated database. Hibernate creates no
  database schema on its own: `hibernate.hbm2ddl.create_namespaces` (JPA
  `jakarta.persistence.create-database-schemas`) defaults to false.

## Idioms & best practices
- Share one named in-memory database across a test's connections with
  `jdbc:h2:mem:<name>;DB_CLOSE_DELAY=-1`.
- When entities name a schema, create it as the connection opens:
  `INIT=CREATE SCHEMA IF NOT EXISTS <schema>`. Observed in practice as the
  working recipe for a schema-qualified mapping; the manual documents `INIT`
  and the command, not the recipe.
- Prefer embedded mode. If a server is needed, bind it to localhost first.
- Keep the default profile safe: a run with no datasource URL silently falls
  back to an in-memory H2 when H2 is on the class path, so do not make the
  profile with no URL the convenient one for anything beyond local work.

## General pitfalls
- **Private in-memory databases.** Two connections to `jdbc:h2:mem:` open two
  different, empty databases; a name is what makes them share one.
- **Lost data at last close.** Without `DB_CLOSE_DELAY=-1` the content of an
  in-memory database goes when the last connection closes.
- **Schema-qualified tables vanish in tests.** On MySQL a schema is a synonym
  for the database, so `@Table(schema = "...")` has no effect there. H2 has
  real schemas, and Hibernate does not create them, so the table and its
  foreign keys are not created and the only sign is a warning in the log.
  Observed in practice (verified): the fix needs both
  `INIT=CREATE SCHEMA IF NOT EXISTS <s>` in the URL and
  `@AutoConfigureTestDatabase(replace = Replace.NONE)`, so the test keeps that
  URL instead of an auto-replaced embedded database. The upstream docs confirm
  each part but do not describe the combined failure.
- **Keywords.** On the 2.x line `USER`, `VALUE`, `YEAR` and other words are
  reserved, so a table or column with such a name fails unless quoted or
  listed in `NON_KEYWORDS`.
- **A green H2 test is not a green production test.** A compatibility mode is
  partial by design: each mode adds only the behaviours its manual entry
  lists, and `H2Dialect` does not support the modes at all. A test on H2
  proves behaviour on H2.
- **A dialect-function alias can be wrong without failing.** `MODE=MySQL` does
  not provide MySQL's `DATE_FORMAT`. Aliasing it to H2's `FORMATDATETIME`
  passes MySQL `%`-patterns to a function that reads `java.time`
  `DateTimeFormatter` patterns, so the query returns a wrong string with no
  error, and the test built on it is green and worthless. Register a test-scope
  function instead (`CREATE ALIAS` on a Java method) that implements the MySQL
  semantics, and assert a known answer.

## Testing
- `@DataJpaTest` replaces the configured data source with an embedded one;
  `@AutoConfigureTestDatabase(replace = Replace.NONE)` keeps the configured
  URL (needed for the `INIT=` recipe above and for a real database).
- Use H2 for fast repository and query tests, with `DB_CLOSE_DELAY=-1` and
  `DB_CLOSE_ON_EXIT=FALSE`. Observed in practice: mapping-sensitive tests run
  better against the production engine in a container (Testcontainers), since
  an H2 mode cannot reproduce it fully.

## Security defaults
- Upstream says H2 is not designed for an adversarial environment: do not
  expose an H2 server to untrusted connections. Embedded mode is the best
  choice; a TCP server should listen on localhost, then only on restricted
  ports of a secured network. TLS is possible but hard to set up right.
- `CREATE ALIAS` can run anything the JVM can, file access included, so any
  user who can run SQL controls the process.
- `-tcpAllowOthers`, `-pgAllowOthers` or `-webAllowOthers` together with
  `-ifNotExists` let remote clients create databases: an open remote hole.
- The console is for development only. Boot's docs say to make sure
  `spring.h2.console.enabled` is not true in production. The console uses
  frames and has no CSRF protection, so under Spring Security its path needs
  CSRF disabled and `X-Frame-Options: SAMEORIGIN`, and only in development.
- Passwords are stored as salted SHA-256; in server mode they are not sent in
  plain text, a protection that does not cover the console or a password set
  in the URL. Database files can be AES-encrypted.

## Operational behaviour
- MVStore, a log-structured multi-version key-value store, is the default
  storage engine. `SHUTDOWN COMPACT` compacts the file.
- Opening a file database creates a lock file. The default locking method,
  `FILE`, runs a watchdog thread that reads the lock file each second;
  `SOCKET` and `FS` are the alternatives, and a database opened without locking
  leaves file protection to the application.
- Opening a connection to an already open database is fast; a pool pays off
  when connections open and close often.

## Interop
- **Spring Boot:** embedded-database auto-configuration, the console, test
  data-source replacement, and the BOM-managed version (above).
- **Hibernate:** dialect choice and schema creation (above); see
  [`hibernate-orm.md`](./hibernate-orm.md).
- **MySQL/MariaDB drivers:** a project often carries H2 beside the production
  driver and switches by profile; see
  [`mysql-connector-j.md`](./mysql-connector-j.md) for the production side.

## Major lines
### 1.x to 2.x
- The change is large enough that upstream says a simple in-place upgrade is
  impossible. The official path: export with `SCRIPT` on the old version,
  create a new database on the new one, and load it with `RUNSCRIPT` (the
  `FROM_1X` flag helps).
- Types on 2.x: `CHARACTER VARYING` holds up to 1,000,000,000 characters (CLOB
  beyond that); `BINARY` is fixed-length and distinct from `BINARY VARYING`;
  `NUMERIC` without parameters has scale 0 (`DECFLOAT` for variable scale);
  `ENUM` ordinals start at 1; arrays are typed.
- Identity on 2.x: use `GENERATED ... AS IDENTITY`; NULL no longer triggers
  generation (outside some modes); `IDENTITY()` and `SCOPE_IDENTITY()` are
  gone in regular mode; vendor-specific identity declarations are deprecated;
  `INFORMATION_SCHEMA` was reworked. Old mapping code that relied on any of
  these breaks on the upgrade.
- Boot 4 ships the console support as its own module, `spring-boot-h2console`.
  How earlier Boot lines packaged it was not confirmed for this page.
