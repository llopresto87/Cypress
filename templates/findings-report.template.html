AUD-37

The bulk export returns another tenant's records when the tenant parameter in the query string is edited

◆Severity: Critical ●Status: Open ▣Where to fix: Application code: example-api Effort: S · half a day
Code references
  • internal/export/handler.go:57-66
  • internal/authz/scope.go:19
Concrete harm
The handler takes the tenant from the request instead of from the signed-in session. Any user of one tenant can download the complete export of every other tenant by changing a single parameter. Each request is authenticated, so nothing in the access log marks it as unusual, and the disclosure is invisible after the fact.
Obligation breached
Source instrument, article and clause “The obligation, quoted verbatim from a retrieved copy of the source.”
Related decision / spec
The decision record that makes the session the only source of tenant scope; the spec clause that pins it down.
Minimal suggested fix

Read the tenant from the verified session and ignore any tenant value the request carries. A session with no tenant is refused.

// export handler: tenant scope comes from the session, never from the request
tenant := authz.TenantFromSession(r.Context())
if tenant == "" {
    http.Error(w, "no tenant in session", http.StatusForbidden)
    return
}
rows, err := store.ExportRows(r.Context(), tenant)

⇄ Cross-reference: see VULN-12 in the security report, which covers the same export from the access-control side.

AUD-46

The API echoes any Origin header back and allows credentials on cross-origin requests

▲Severity: High ◐Status: Partial ▣Where to fix: Application code: example-web Effort: M · 1–2 days
Code references
  • server/middleware/cors.ts:31-39
Concrete harm
Any web page a signed-in user happens to open can call the API with that user's cookies and read the answers, profile and account data included. The user sees nothing. The admin routes already check an allowlist; the account routes still echo whatever origin asks.
Obligation breached
Source instrument, article and clause “The obligation, quoted verbatim from a retrieved copy of the source.”
Related decision / spec
No related decision recorded.
Minimal suggested fix

Move the account routes onto the allowlist the admin routes already use, answer an unlisted origin with no CORS headers at all, and add a test that sends a foreign origin and expects no Access-Control-Allow-Origin in the reply.

AUD-52

The release image builds from a floating base tag, so a rebuild of the same commit can ship code nobody reviewed

▲Severity: High ■Status: Blocked ◈Where to fix: Platform layer: example-infra Effort: L · 3 days or more
Code references
  • build/Containerfile:1
  • ci/release.yaml:33-35
Concrete harm
Every build pulls whatever the upstream tag points to that day. Two releases of the same commit can differ, the build record cannot say which base image went out, and a tampered upstream tag would reach production with no review step in between. The audit trail for a release therefore proves less than it claims. Pinning waits on an internal mirror of the base image, which another team owns.
Obligation breached
Source instrument, article and clause “The obligation, quoted verbatim from a retrieved copy of the source.”
Related decision / spec
The spec section that defines how release artifacts are built and recorded.
Minimal suggested fix

Pin the base image by digest and make the release job refuse an unpinned reference, so a floating tag fails the build instead of shipping.

# Containerfile: a tag alone moves; the digest is what was reviewed
FROM registry.example.org/runtime/base:stable@sha256:<digest recorded at review>

⇄ Cross-reference: see VULN-29 in the security report for the same build step seen from the supply-chain side.
